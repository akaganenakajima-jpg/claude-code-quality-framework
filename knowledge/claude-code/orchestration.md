# オーケストレーション — エージェントを束ねて並列・大規模に動かす

> 最終検証日: 2026-06-16 ／ 出典 `https://code.claude.com/docs`。挙動は使用前に公式ドキュメントで再確認。

## 1. サブエージェント

専門化した別エージェントに作業を委譲する仕組み。**親とは独立したコンテキストウィンドウ**で動き、最終結果（サマリー）だけを親に返す。

- **いつ使うか**: 探索的なタスク（広範な検索・ログ出力・大量ファイル読み）で**親の会話コンテキストを圧迫したくない**とき。同種のワーカーを繰り返し生成するとき。
- **定義**: `.claude/agents/`（プロジェクト）または `~/.claude/agents/`（ユーザー）に配置。`description` を明確に書くと自動委譲の判断に使われる。
- **注意**: サブエージェントが返すのは「最終テキスト＝戻り値」。人間向けの前置きではなく構造化データを返させると扱いやすい。委譲しすぎると往復コストが増えるため、2〜3ファイルで済むなら自分でやる（CLAUDE.md「サブエージェントの使い分け」）。
- 出典: https://code.claude.com/docs/en/sub-agents

## 2. 並列エージェント実行

独立した複数の調査を**1メッセージ内で同時にディスパッチ**すると並行実行される。

- **いつ使うか**: 互いに依存しない調査・レビューが3つ以上あるとき（例: セキュリティ分析・性能レビュー・型チェックを同時に）。
- **原則**: 依存がある作業は順次、独立なら並列。結果を全部揃えてから次に進む必要がある場合のみ「バリア（全完了待ち）」にする。
- **注意**: 並列数には上限がある。失敗したエージェントの結果は欠落しうるので、使う前に有無を確認する。

## 3. Workflow（大規模オーケストレーション）

スクリプトで**多数のサブエージェントを動的に調整**し、コードベース監査・大規模マイグレーション・横断レビューなど1コンテキストに収まらない作業を回す。

- **いつ使うか**: 数十〜数百ファイルの一括変換、網羅的レビュー（発見→敵対的検証→統合）、1セッションでは持ちきれない規模の作業。
- **代表パターン**: パイプライン（各項目を全ステージへ独立に流す）／ファンアウト＋バリア（全結果を集約してから次へ）／ループ・アンティル・ドライ（新規検出がK回連続ゼロまで探索）。
- **注意**: トークン消費が大きい。**ユーザーが明示的にオプトインした場合のみ**起動する（無断で大量エージェントを走らせない）。本フレームワークのリスク判定では🟠〜🔴相当の段取りとして扱う。
- 出典: https://code.claude.com/docs/en/workflows

## 4. Agent View / バックグラウンドエージェント

複数の Claude Code セッションを1画面で管理する。各セッションは「Needs input / Working / Completed」で分類され、進行中のものに戻って入力・返信できる。

- **いつ使うか**: 独立タスクを複数同時に走らせ、まとめて進捗監視したいとき。長時間処理をバックグラウンドに逃がして会話を止めたくないとき。
- **呼び出し**: CLI `claude agents`。デスクトップアプリでも並行セッションを表示できる。
- 出典: https://code.claude.com/docs/en/agent-view

## 5. Worktrees — 隔離環境で安全に実験

git worktree を使い、同一リポジトリの**別ブランチ・別作業ディレクトリ**でセッションを分離する。失敗しても worktree を消すだけで本番は無傷。

- **いつ使うか**: 「試しに〜したい」「大幅に変えたい」「壊れても構わない」系。本フレームワークの🔴最高リスク作業（DB構造変更・定期実行変更・本番公開）の標準手段。
- **組み合わせ**: 並列セッション／バックグラウンドエージェントと併用すると、作業ディレクトリ競合を避けつつ複数フィーチャを同時開発できる。
- 出典: https://code.claude.com/docs/en/worktrees
