# オーケストレーション — エージェントを束ねて並列・大規模に動かす

> 最終検証日: 2026-11-27 ／ Claude Code v2.1.332 ／ 出典 `https://code.claude.com/docs`。挙動は使用前に公式ドキュメントで再確認。

## 1. サブエージェント

専門化した別エージェントに作業を委譲する仕組み。**親とは独立したコンテキストウィンドウ**で動き、最終結果（サマリー）だけを親に返す。

- **いつ使うか**: 探索的なタスク（広範な検索・ログ出力・大量ファイル読み）で**親の会話コンテキストを圧迫したくない**とき。同種のワーカーを繰り返し生成するとき。横断調査・多ファイル監査・長期タスクの別コンテキスト検証のように**独立して並行できる大きな作業**。
- **定義**: `.claude/agents/`（プロジェクト）または `~/.claude/agents/`（ユーザー）に配置。`description` を明確に書くと自動委譲の判断に使われる。
- **モデル・effort の指定**: 呼び出し時の Agent ツール引数（`model` はエイリアスのみ。`effort` は v2.1.292 以降で、利用者か CLAUDE.md・スキルが明示したときだけ使う）か、定義の frontmatter の `model` / `effort`。作業に応じた選び方は `model-routing.md` §3。
- **CLAUDE.md の継承**: カスタムと汎用のサブエージェントには CLAUDE.md が全階層読み込まれる。組み込みの Explore・Plan は読まない。frontmatter の `omitClaudeMd: true`（v2.1.271 以降）で外せるが、CLAUDE.md の規則も届かなくなるので、委譲文だけで足りる読むだけの検索・要約用に限る。
- **並列の上限**: 同時に動かせるのは 20 体まで（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` で変更可）。入れ子は既定で3層まで（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` で変更可）。メイン会話から起動したカスタムサブエージェントは既定でバックグラウンドで動く。
- **注意**: サブエージェントが返すのは「最終テキスト＝戻り値」。人間向けの前置きではなく構造化データを返させると扱いやすい。委譲にはブリーフィングと結果統合の固定コストがあるため、2〜3ファイルで済む作業は自分でやる（CLAUDE.md「サブエージェントの使い分け」）。頻度の上限は設けず、独立・並列なら非同期で委譲して自分の作業を続ける（`agentic-operating.md` §6, §9）。
- 出典: https://code.claude.com/docs/en/sub-agents

## 2. 並列エージェント実行

独立した複数の調査を**1メッセージ内で同時にディスパッチ**すると並行実行される。

- **いつ使うか**: 互いに依存しない調査・レビューが3つ以上あるとき（例: セキュリティ分析・性能レビュー・型チェックを同時に）。
- **原則**: 依存がある作業は順次、独立なら並列。結果を全部揃えてから次に進む必要がある場合のみ「バリア（全完了待ち）」にする。
- **注意**: 並列数には上限がある（同時 20 体まで。§1）。失敗したエージェントの結果は欠落しうるので、使う前に有無を確認する。

## 3. Workflow（大規模オーケストレーション）

スクリプトで**多数のサブエージェントを動的に調整**し、コードベース監査・大規模マイグレーション・横断レビューなど1コンテキストに収まらない作業を回す。

- **いつ使うか**: 数十〜数百ファイルの一括変換、網羅的レビュー（発見→敵対的検証→統合）、1セッションでは持ちきれない規模の作業。
- **代表パターン**: パイプライン（各項目を全ステージへ独立に流す）／ファンアウト＋バリア（全結果を集約してから次へ）／ループ・アンティル・ドライ（新規検出がK回連続ゼロまで探索）。
- **オプトイン**: 起動するのは、利用者が頼んだとき（「workflow で」など自分の言葉、またはプロンプトに `ultracode` を含める）か、`/effort ultracode` でセッション全体をオンにしているときだけ。`/deep-research` も Workflow で動く。ultracode はタスクごとに Workflow を組むので、トークンも時間も増える。
- **Large workflow 警告**: 25 体を超えるエージェントを予定するか、見込みが 150 万トークンを超えると進捗行に表示される。`/workflows` から止められる（ultracode オンのときは出ない）。
- **モデル**: Workflow のエージェントのモデルはサブエージェントと同じ順で決まる。スクリプトが指定したモデルは呼び出し時の指定として扱われ、指定が無ければセッションのモデルで動く。段ごとの選び方は `model-routing.md` §3。
- **注意**: トークン消費が大きい。**ユーザーが明示的にオプトインした場合のみ**起動する（無断で大量エージェントを走らせない）。本フレームワークのリスク判定では🟠〜🔴相当の段取りとして扱う。
- 出典: https://code.claude.com/docs/en/workflows

## 4. Agent View / バックグラウンドエージェント

複数の Claude Code セッションを1画面で管理する。各セッションは「Needs input / Working / Completed」で分類され、進行中のものに戻って入力・返信できる。

- **いつ使うか**: 独立タスクを複数同時に走らせ、まとめて進捗監視したいとき。長時間処理をバックグラウンドに逃がして会話を止めたくないとき。
- **呼び出し**: CLI `claude agents`。デスクトップアプリでも並行セッションを表示できる。
- 出典: https://code.claude.com/docs/en/agent-view

## 5. Worktrees — 隔離環境で安全に実験

git worktree を使い、同一リポジトリの**別ブランチ・別作業ディレクトリ**でセッションを分離する。失敗しても worktree を消すだけで本番は無傷。

- **いつ使うか**: 「試しに〜したい」「大幅に変えたい」「壊れても構わない」系。本フレームワークの🔴最高リスク作業（DB構造変更・定期実行変更・本番公開）の標準手段。
- **組み合わせ**: 並列セッション／バックグラウンドエージェントと併用すると、作業ディレクトリ競合を避けつつ複数フィーチャを同時開発できる。
- 出典: https://code.claude.com/docs/en/worktrees

## 6. 関連（詳細は公式ドキュメント）

- **Agent Teams**: 複数セッションをチーム化し、相互通信・タスク共有・結果マージを行う。サブエージェントより相互依存が重いケース向け。**実験的機能で既定は無効**（`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効化）。1セッションに1チームまで、チームの入れ子は不可、`/resume`・`/rewind` では in-process のチームメイトが復元されない。分割ペイン表示は tmux か iTerm2 が必要（既定の in-process 表示は任意のターミナルで動く）。 https://code.claude.com/docs/en/agent-teams

## 7. 並列手段の比較

| 手段 | 向く場面 | 注意 |
|---|---|---|
| サブエージェント | 独立した調査・検証。結果の要約だけ親に返したい | 同時 20 体まで。モデル・effort の選び方は `model-routing.md` §3 |
| Workflow | 数十〜数百項目の一括処理・網羅レビュー | オプトインのみ。Large workflow 警告（25 体超・150 万トークン超） |
| agent teams | 互いに連絡しながら進める作業 | 実験的で既定は無効。1セッション1チーム |
| Worktree | 同じファイルを触る並列作業の隔離 | サブエージェントにも別セッションにも併用できる（§5） |
| 別セッション | 独立した成果（ブランチ・PR など）で終わる別タスク | 今の作業の一部なら、別セッションにせずサブエージェントか自分で行う |

別セッションに連絡・依頼する、完了を待つ、といったやりとりのルール（受ける側・送る側・承認の境界・設定）は `cross-session.md` を参照。
